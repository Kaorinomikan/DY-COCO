# 更新日志阅读设计（评审稿）

目标：商家扫一眼知道这版有什么变化、对自己有什么用。

## 窗口

- 保留反馈/更新日志双页签、版本日期和当前版本标记。
- 版本号 15px 半粗体，一句话概括 17px 半粗体；要点标题 14px 半粗体，解释 13px、行高 1.75。
- 每版 1–5 条，用①②③顺序编号；编号与文字分列，换行后正文对齐。
- 每条先说变化，再用一行说明好处；条目间距 16px。旧版本的标题更弱，用分隔线区分。
- 沿用橙色强调，正文用深灰；仅编号、当前版本与选中页签用橙色。
- 日志继续向下滚动读取；页面内面板与独立小窗口同步调整。

## 文案示范（重述 26.11.10.2，非新版本发布承诺）

一句话：开关保存更稳，菜单更好懂。

① 开关设置能正常保存

解决部分浏览器保存失败的问题，保存没成功会明确提醒。

② 菜单说明更好懂

用途和注意事项更清楚，两处服务平台跳转现在只用一个开关。

③ 拖动时换上猫爪光标

鼠标移上去张开，按住时收拢，拖动状态更直观。

## 文案审阅

- 每条都能回答「用户得到什么」，删掉函数、接口、通信与重试细节。
- 有收益才写性能；数字必须有对照实测，未测不作保证。
- 无明显变化时不凑性能卖点；需要说明且有依据时，写「性能表现基本不变」。
- 不自动润色远端旧日志，以免改写事实；当前发布文案在发布时按新规则整理。

本稿仅调整规则和设计，尚未修改插件窗口或发布日志。
