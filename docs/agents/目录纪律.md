# 目录纪律 · 入口层只放项目

> 归属：AGENTS.md 第 28 条。判据在 `scripts/check-root-clean.py`（已接入 publish.sh），
> 本文只解释口径与去向，不重复规则。

## 一、两级定位

| 层 | 路径 | 允许放什么 |
|---|---|---|
| 入口层 | `C:\Develop project` | **只放项目目录**。今后别的项目（小程序、尺码表等）各占一个目录，互不干扰 |
| 工程层 | `C:\Develop project\DY-COCO` | 代码 + 本工程的**全部**本机文件（配置、发布包、工作树、设计稿、诊断脚本） |

判据机械可查：入口层出现散落文件，或某个目录不含 `.git` / `manifest.json` /
`package.json`，闸门即判失败。系统生成的 `desktop.ini` 等不计。

**源码唯一位置 = 工程层**（2026-11-22 用户定）：所有源码、脚本、文档、配置一律
只存在于 `C:\Develop project\DY-COCO` 之内，工程目录以外不放任何源码副本。
桌面 `COCO TEST` 是**浏览器加载用的运行镜像**，只由 `scripts/sync-coco-test.sh`
单向写入 —— 它不是工作目录、不存源码、不在里面改代码，改了会被下次同步覆盖。

## 二、本机文件去向表（2026-11-22 搬迁后的定版）

| 东西 | 放哪 | 入库？ |
|---|---|---|
| 令牌 / 词表 / 截图 key | `.dyc-config/` | 否（整目录 gitignore） |
| 临时、存档、旧备份 | `.tmp/`（旧件进 `.tmp/attic/`） | 否 |
| 端口/便携运行时 | `.tmp/runtime/` | 否 |
| 分发包 zip | `dist/` | 否 |
| 并行开发工作树 | `.worktrees/<任务名>/` | 否 |
| 设计稿、评审稿 | `docs/design/` | 是 |
| 单文件诊断扩展 | `scripts/live-diag/` | 是 |

搬迁前的旧位置：`../.dyc-*`、`../DY-COCO-dist`、`../DY-COCO-wt`、`../DY-COCO-design`、
`../DY-live-diag` —— **全部作废**，脚本与文档已同步改口径。

## 三、新机器 / 新会话注意

- `.dyc-config/` 不入库，克隆到新机器后需**手工重建**（把令牌与词表放回去），
  否则敏感词闸门会以「词表缺失」中止 —— 这是有意的硬失败。
- 工作树在 `.worktrees/` 下，词表仍由 `check-sensitive-words.py` 经
  `--git-common-dir` 反推主仓库后共用那一份，**不要往工作树里拷词表**。
- 想在入口层新建任何东西前先问：它是「另一个项目」吗？不是就下沉。
